# Proposal: Mobile Mastery New UX Concepts
Generated by: cm-brainstorm-idea
Date: 2026-06-30

## Why We're Doing This

The current mobile Mastery screen is constrained by its existing shape: header, stats, filters, card list, and a small detail sheet. The user requested new UI/UX ideas that do not depend on the current screen. This proposal explores fundamentally different product metaphors for the same underlying job.

### Qualified Problem

For mobile learners who open Sổ tay to find, understand, and act on learned vocabulary, the current archive behaves like a compressed desktop table/dashboard. It is not optimized around the mobile learning jobs:

- "Find the word I need now."
- "Understand this word deeply."
- "Know what needs review next."
- "Save or write memory cues quickly."

Unlike the current list-first layout, the next design should choose a stronger mobile-native metaphor and make the first screen immediately useful.

### Root Causes

1. Product: Sổ tay mixes archive, stats, filters, review selection, notebook saving, and detail reading in one surface.
2. Design: the current layout gives equal visual weight to low-value metadata and high-value word content.
3. Technical: mobile detail currently uses a reduced `MasteryWord` shape while richer word fields exist elsewhere.

## Options Evaluated

### Option A: Command Palette Archive

**Approach:** Make Sổ tay feel like a fast searchable command center. The first screen is a search-led archive with a compact "review queue" and recent/weak words below.

**Philosophy:** Utility-first.

**What changes:**

- Search becomes the hero input.
- Filters are natural language chips: `Đến hạn`, `Yếu`, `Đã lưu`, `Có ghi chú`.
- Results are dense rows.
- Detail opens as a full-height dossier with tabs.

**Effort:** M
**Risk:** Low-Medium

**Pros:**

- Very fast to use.
- Strong fit for repeated lookup.
- Technically close to current data flow.

**Cons:**

- Less emotionally distinctive.
- Still primarily list/search driven.

**Best when:** The priority is speed, density, and low implementation risk.

### Option B: Memory Inbox

**Approach:** Turn Sổ tay into a daily triage surface. Instead of showing all words first, it opens with "Hôm nay cần xử lý gì": due words, weak words, recently added words, and saved notebook words.

**Philosophy:** Action-first.

**What changes:**

- First screen has 3 action lanes:
  - `Cần ôn`
  - `Đang yếu`
  - `Mới lưu`
- Each lane has horizontal compact cards.
- Search is always available but secondary.
- Tapping a word opens a rich dossier.
- Batch study starts from lane actions rather than checkboxes.

**Effort:** M-L
**Risk:** Medium

**Pros:**

- Strongly supports learning behavior, not just storage.
- Reduces filter complexity.
- Makes Sổ tay feel alive and useful every day.

**Cons:**

- Needs careful empty states.
- Requires slightly more product logic around grouping/prioritization.

**Best when:** The priority is helping learners decide what to do next.

### Option C: Word Dossier Shelf

**Approach:** Make Sổ tay a library of rich word dossiers. The first screen is a visual shelf/index: alphabet jump, topic shelves, and recently opened dossiers. Each word opens into a deep "case file."

**Philosophy:** Knowledge-first / premium learning.

**What changes:**

- Main navigation is by topic/letter shelves.
- Cards are slimmer but more book-like.
- Detail page is the star: definition, examples, Vietnamese translation, word family, synonyms, antonyms, memory note, FSRS stats.
- Optional notebook metaphor can be integrated without opening the separate book spread.

**Effort:** L
**Risk:** Medium-High

**Pros:**

- Most differentiated and premium.
- Best answer to "desktop has more information, mobile must show it too."
- Can become the canonical mobile knowledge surface.

**Cons:**

- Heavier design/build effort.
- Must avoid becoming decorative or slow.

**Best when:** The priority is making VocaFlash feel like a serious vocabulary knowledge system.

## Recommendation

Choose **Option B: Memory Inbox**, with the detail depth of **Option C**.

### Why

1. It breaks free from the current archive/table shape.
2. It centers the learner's real mobile job: "what should I handle now?"
3. It removes bulky filter logic by replacing it with meaningful learning queues.
4. It still allows a full searchable archive as a secondary tab/search mode.
5. It creates room for a rich word dossier without overloading the first screen.

### Why Not the Others

- **Option A:** likely becomes a better version of the current list, not a new UX idea.
- **Option C:** beautiful and deep, but risks becoming a big redesign before the daily-use behavior is proven.

## Proposed Direction

Build a new mobile Mastery concept around three top-level modes:

1. **Inbox**
   - Due now
   - Weak words
   - Recently saved
   - Quick study actions

2. **Archive**
   - Search
   - A-Z
   - Topic
   - compact result rows

3. **Dossier**
   - Full word detail
   - Overview / Linguistic / Notes / Stats
   - Uses enriched word data on demand
