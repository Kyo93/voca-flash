# Proposal: Mobile Codex Minimal Redesign
Generated by: cm-brainstorm-idea + cm-ux-master
Date: 2026-06-28

## Why we're doing this

### Qualified Problem

For Vietnamese mobile learners on an S25 Ultra-class viewport around 390x850, VocaFlash has the right learning features but the mobile UI still feels visually heavier than the requested target.

The current mobile surface uses many rounded cards, warm containers, gradients, blur/backdrop effects, and visible rings. This makes each screen feel like a collection of decorated modules instead of a calm app workspace. The desired direction is closer to the Codex app: minimal, flat, crisp, text-led, and task-focused, while still reusing the Desktop Tactile Scholar palette for brand continuity and maintainability.

### 9 Windows Analysis

| Level | Past | Present | Future |
| --- | --- | --- | --- |
| Super-system | Mobile learning apps often used playful colors and card-heavy gamification. | Power-user AI/productivity apps now normalize quiet, dense, highly legible mobile workspaces. | A vocabulary app can feel scholarly and premium by becoming calmer, not more decorative. |
| System | VocaFlash started with a tactile scholar desktop identity. | Mobile parity exists across Dashboard, Library, Roadmap detail, Study, Review, Mastery, Profile, Characters, Achievements, Settings, Landing, and Login. | Mobile should have its own coherent app-native foundation while preserving desktop identity. |
| Sub-system | Individual screens accumulated local Tailwind treatments. | Mobile components repeat `rounded-3xl`, shadows, rings, warm fills, blur headers/nav, and large decorative hero cards. | Shared mobile primitives should define shell, section, row, card, controls, bottom sheets, and focus screens. |

### Root Causes

1. Mobile screens are implemented as one-off polished views, not as a shared mobile design system.
2. Visual hierarchy relies too much on container styling instead of typography, spacing, and content order.
3. Bottom navigation and sticky bars use blur/shadow treatments that conflict with the requested Codex-like minimalism.
4. Study and Review focus screens keep some high-drama styling from the previous learning-arena direction.

### Impact if not addressed

- The app will feel less professional than the user wants, even if functions work.
- Mobile screens will continue to drift visually as new features are added.
- Learners may spend more attention parsing visual decoration than choosing the next study action.
- S25 Ultra optimization will remain fit-oriented rather than interaction- and aesthetic-oriented.

## What's changing

### Options Evaluated

#### Option A: Foundation-First Minimal Skin

Create a Codex-like mobile foundation with flat surfaces, small radius, hairline borders, no blur, no decorative shadows, restrained use of the existing desktop palette, and consistent 44px touch targets. Apply it across the mobile shell and all existing mobile views with scoped CSS and targeted component updates.

Effort: M, Risk: Low-Medium.

#### Option B: Screen-by-Screen Full Rewrite

Rewrite each mobile screen component into a strict native-style layout from scratch: Dashboard, Library, Topics, Mastery, Progress, Achievements, Characters, Settings, Study, Review, Landing, Login.

Effort: XL, Risk: High.

#### Option C: Focus-Flow Redesign Only

Limit changes to learning-critical screens: Dashboard, Library, Study Prep, Study Card, Review Arena, and Mastery. Leave Profile, Settings, Characters, Landing, and Login mostly as-is.

Effort: M, Risk: Medium.

### Recommendation

Choose Option A: Foundation-First Minimal Skin.

It gives the whole mobile app a coherent Codex-like direction quickly while preserving current data flows, i18n, tests, and desktop behavior. Option B is visually ideal but too risky for a broad app. Option C improves the learner journey but leaves profile/settings/landing visually inconsistent.

## UX Laws Applied

- Fitts's Law: all mobile interactive controls keep at least 44px target size.
- Hick's Law: screens should expose one primary action and move secondary actions into rows, filters, or detail sheets.
- Miller's Law: dashboards group stats into compact chunks instead of many unrelated cards.
- Doherty Threshold: loading, empty, and active states remain visible and responsive.
- Nielsen consistency: shell, rows, buttons, and bottom sheets should look and behave consistently across screens.
- Krug scanability: headings and actions must be obvious without reading all copy.
