# Design: Mobile Mastery Memory Inbox
Generated by: cm-planning
Date: 2026-06-30

## Context & Technical Approach

User chose the recommended direction from brainstorming: **Option B: Memory Inbox**, combined with **Option C's rich Dossier depth**.

This replaces the current mobile Mastery mental model:

- Old: dashboard stats + filters + large word cards.
- New: learning triage inbox + searchable archive + deep word dossier.

The goal is not to make the current screen prettier. The goal is to make mobile Sổ tay answer:

1. What should I handle now?
2. Which words are weak or due?
3. Where can I find any word quickly?
4. Can I open a word and see full learning context?

## Product Model

### Top-Level Modes

Use two primary modes in the mobile Sổ tay surface:

1. **Inbox**
   - Default landing mode.
   - Shows actionable queues, not all words.
   - Optimized for daily learning decisions.

2. **Archive**
   - Search and browse all tracked words.
   - Optimized for lookup.
   - Uses compact dense rows.

Word detail opens as a third layer:

3. **Dossier**
   - Full word profile.
   - Tabs: Overview, Linguistic, Notes, Stats.
   - Uses enriched detail data on demand.

### Inbox Queues

Inbox should group words into meaningful learning queues:

- **Cần ôn**: words due now.
- **Đang yếu**: weak words, based on existing weak filter/stability/lapses.
- **Mới lưu**: notebook-saved words or recently touched words.
- Optional later: **Vừa học** if recent history becomes reliable.

Each queue:

- Has a clear title and count.
- Shows 2-4 compact word chips/cards.
- Has a `Học nhóm này` / `Xem tất cả` action where useful.
- Has an empty state that teaches the user what it means.

### `src/components/mobile/MobileMasteryView.tsx`

Refactor from a single list/filter screen into a mode-based surface:

- Header:
  - `Sổ tay`
  - compact learning summary, e.g. `7 cần ôn · 57 từ`
  - notebook action chip.
- Mode switch:
  - `Inbox`
  - `Archive`
- Inbox mode:
  - Due queue.
  - Weak queue.

  - Search input.

  - 44px touch targets for select/save.
  - word, IPA, short meaning.
  - one metadata line: topic, due date, stability.

### Detail Data Contract

Current `MasteryWord` is intentionally lighter than the full `Word` model. Dossier needs richer fields:

- `pos`
- `difficulty`
- `example_vi`
- `synonyms`
- `antonyms`
- `word_family`
- `image_position`

Plan:

- Add `MasteryWordDetail` type.
- Add storage helper in `src/lib/storage/mastery.ts`, for example `getMasteryWordDetail(wordId)`.
- Fetch from `words` by `id`.
- Merge with the selected `MasteryWord`.
- Cache detail by `word_id` in mobile state to avoid repeat fetches.
- Fallback gracefully to existing `MasteryWord` when detail fetch fails.

No Supabase migration is required for the first version.

### Dossier UX

Use a full-height or near-full-height mobile sheet, not the current small summary sheet.

Header:

- word
- IPA
- topic
- stability/due status
- close
- notebook action
- audio action if available via existing `AudioButton` pattern.

Tabs:

- `Tổng quan`
  - definition
  - example
  - Vietnamese example if available
  - image if available
- `Ngôn ngữ`
  - POS
  - word family
  - synonyms
  - antonyms
  - empty state if no enriched linguistic data
- `Ghi chú`
  - current note
  - edit/save/cancel using existing `onSaveNote`
- `Thống kê`
  - FSRS stability/difficulty/reps/lapses
  - next review
  - mastered/due state

## Assumptions

- Verified: mobile target is S25 Ultra `390x850`.
- Verified: desktop Mastery must remain unchanged.
- Verified: current mobile data supports due/weak/grouping enough for first Inbox.
- Verified: richer detail fields exist in the `Word` model and notebook storage path.
- Assumption: on-demand detail fetch by `word_id` is acceptable for first open latency.
- Assumption: "Mới lưu" can initially mean notebook-saved visible words, not a perfect global recent-saved feed.

## Out of Scope

- Desktop redesign.
- Notebook book UI redesign.
- FSRS algorithm changes.
- New DB migrations unless detail fetch proves impossible.
- Perfect global saved-word feed across unloaded pages. First version can group from loaded/visible words plus notebook state.
