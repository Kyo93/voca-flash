# Proposal: UI/UX Learning Audit
Generated by: cm-brainstorm-idea
Date: 2026-06-28

## Why we're doing this

### Qualified Problem

For Vietnamese learners using VocaFlash to build English vocabulary habits, the current app already has a strong tactile-scholar identity and broad feature coverage, but a few screens break trust and flow at important moments.

The product needs a polish pass that prioritizes learning confidence: screens should load into clear next actions, labels must be fully localized, and dense scholarly surfaces must stay stable at the 1440px desktop baseline and S25-class mobile width.

### 9 Windows Analysis

| Level | Past | Present | Future |
| --- | --- | --- | --- |
| Super-system | Vocabulary apps were flashcard-first and utility-driven. | Learners expect mobile-native habit loops, instant feedback, and polished localization. | Apps that feel trustworthy, calm, and adaptive will retain learners longer than feature-heavy tools. |
| System | VocaFlash focused on SRS, roadmap, mastery, and notebook expansion. | Core surfaces exist: Dashboard, Library, Study, Review, Mastery, Progress, Characters, Settings, Admin. | The app should feel like one coherent learning cockpit across desktop and mobile. |
| Sub-system | Components grew screen-by-screen with recent mobile and notebook refinements. | Evidence shows desktop Mastery overflow, missing i18n keys, direct Study loading trap, and undersized controls. | Shell/layout contracts, i18n completeness, and resilient loading/error states should be treated as quality gates. |

### Root Causes

1. Layout contracts are not consistently enforced across AppLayout, wide content pages, and RightSidebar.
2. i18n keys are referenced before translations are complete or encoded correctly.
3. Async study initialization can leave the learner in an indefinite loading state when Supabase/RPC fetch fails.
4. Desktop controls still use visual-size conventions below the 44px ergonomic target used on mobile.

### Impact if not addressed

- Learners see raw keys like `settings.profile` or `admin.words.title`, reducing confidence in the product.
- A direct Study entry can look broken instead of guiding the learner back to a roadmap/topic.
- Mastery desktop creates horizontal scroll and clipped sidebar content at the target 1440px width.
- Admin and dense table actions remain harder to scan/click, increasing operational mistakes.

## What's changing

### Options Evaluated

#### Option A: Trust & Flow Fix Pass

Fix the highest-confidence UX defects first: Mastery desktop overflow, missing/garbled i18n, Study loading/error fallback, and 44px touch/click target contract for global controls.

Effort: M, Risk: Low.

#### Option B: Learner Journey Redesign

Reframe Dashboard, Library, Study Prep, Review, and Mastery around one primary learner journey: "what should I do next?" with reduced secondary CTAs and clearer habit progression.

Effort: L, Risk: Medium.

#### Option C: Design System Hardening

Create stricter layout, token, interaction, and i18n gates; migrate direct colors and screen-specific styling into reusable patterns before broad UI polish.

Effort: L, Risk: Low-Medium.

### Recommendation

Choose Option A first: Trust & Flow Fix Pass.

It removes visible trust-breakers quickly while preserving the current product direction. Option B should follow once the experience is stable. Option C should run alongside future feature work as quality gates, but it should not delay the immediate learner-facing fixes.

## Evidence From Audit

- Desktop 1440x900 and mobile 412x915 were smoke-tested through Playwright on current local app.
- Screens covered: public landing/login, Dashboard, Library, Progress, Achievements, Characters, Settings, Methodology, Mastery, Study, Review, Free Study, Admin dashboard/words/roadmaps/users.
- No critical console errors on normal route rendering, but direct `/study` stayed on spinner for 20 seconds after a fetch failure.
- Desktop `/mastery` measured `scrollWidth=1670` at `clientWidth=1440`; RightSidebar begins outside the viewport.
- Mobile surfaces generally avoid horizontal overflow, but Settings and Mastery still have small controls/inputs below the 44px target.
- Admin Words exposes missing translation keys: `admin.words.title`, `admin.words.count`, `admin.words.addWord`.
- Settings exposes missing translation key: `settings.profile`.
- Admin sidebar Vietnamese title is mojibake: `B?ng qu?n tr?`.
